# v0.3.1 Feed 性能优化验收

日期：2026-10-02。执行已确认的 [优化计划](v0.3.1_FEED_OPTIMIZATION_PLAN.md)，保留工作区原有未提交改动，未提交 Git、迁移数据库或激活新模型。

## 结果

普通新版全部推荐、热门和探索的前台生成不再同步召回或补详情。先用完整候选通过原过滤、质量闸门、冷却、排序和 Mixer 成页，不足时返回短页或空页，后台按真实成页能力补池；用户稍后手动换一批，已有缓存页不改写。

每组 50 次 HTTP 验收结果如下。计时包含 Flask Feed 服务和响应 JSON 构造，不包含浏览器传输、布局和绘制。

| 场景 | 样本数 | p50 ms | p95 ms | 最大 ms | API / detail 请求 |
| --- | ---: | ---: | ---: | ---: | --- |
| 完整热候选生成新批次 | 50 | 156.34 | 271.26 | 444.23 | 全部 0 / 0 |
| GET 重读同一缓存页 | 50 | 7.16 | 7.35 | 7.39 | 全部 0 / 0 |
| POST 同 view 重试刷新 | 50 | 7.87 | 8.26 | 10.55 | 全部 0 / 0 |
| 另一 stream 生成期间读取缓存 | 50 | 6.80 | 7.24 | 20.52 | 全部 0 / 0 |
| 同 stream 下一页生成期间读取缓存 | 50 | 6.82 | 7.20 | 7.39 | 全部 0 / 0 |

50 个热候选新批次均返回 12 条。达到新页 p50 < 500 ms、p95 ≤ 1 s，以及缓存竞争 p95 ≤ 200 ms 的计划目标；保留最大值，未删除离群样本。

方法：只读备份生产数据库，使用临时副本；固定当前活动模型 `baseline-v02-f6309d9ab2a7cb2e` 和新版来源设置（hot=fallback、rcmd=small）。预热模型后，每次新页样本先恢复同一快照并清除过滤缓存，恢复操作在计时之外。禁用该临时进程的后台启动及 prefetch，并令外部请求入口直接失败，保证测量不依赖外网。竞争场景用事件暂挂生成请求的准备阶段，持续读取已经生成的第 0 页，然后释放并完成竞争请求。

保存数据：`.tmp/feed-optimization/acceptance-final/traces.jsonl` 和 `summary.csv`。兼容旧动态发布时间之前的首轮验收也保留在 `acceptance/`，其新页 p95 为 257.53 ms、同 stream 竞争最大值为 140.78 ms。最终表使用兼容修复后重新采集的全部样本。可复验：

```powershell
.venv\Scripts\python.exe -W ignore -m backend.tools.feed_performance --benchmark --repeats 50 --output .tmp/feed-optimization/acceptance-final
```

第一轮优化前的两批真实服务调用为 16.372 / 14.448 s，API 为 17 / 15 次、detail 均为 12 次，主要耗时是同步详情、召回及其一秒节流；详见 [第一轮诊断](v0.3.1_feed_performance_report.md)。这些旧样本与本表的 HTTP 50 次验收口径不同，不能当作同条件 p95 比较。优化后热新页的 rank 中位数为 15.94 ms、mixer 为 0.34 ms，生成锁等待为 0.004 ms，队列与节流等待均为 0。

## 已落地的边界

- 普通入口零同步网络；具体分区新 stream 首屏只在原 Mixer 无法填满时 raw-first，最多一个 related 种子召回、min(缺口, 2) 次详情发送尝试。recent / discover 不进入分区例外。
- 关注新 stream 首屏只取最新 head，不同步翻旧 offset；最多 min(最新缺口, 3) 次详情发送尝试。只展示已完整的最新前缀，不能跳过缺详情的新视频去填旧视频。head 失败明确显示本地时间线降级，同 view 重试和分页不反复取 head。
- 网络例外共用 5 秒软预算，涵盖排队、签名依赖和重试退避；到期停止尚未发送的尝试，在途请求仍可能超过 5 秒。关注和分区的必要网络不套用零网络热页目标。
- 真正发送层统一计数初发、nav、重试和重定向，保留一秒最小间隔与风控退避。同级 FIFO；连续三次前台后给予一个已可发送的后台请求，后台不预占未来发送槽。
- 后台低于两页真实 Ready 时补至三页，最多八个近期需求、十分钟失效；每轮最多 12 次详情和 3 次召回发送尝试。完成标记、过滤、来源条件、质量与原 Mixer 都参与 Ready 判断，不用 raw 数量冒充缓冲。
- 每个 stream 串行生成；已有缓存页绕过生成锁。全局锁只用于 stream 创建/实验分组和最终重查、选择、提交，网络和节流在锁外。最终提交重查跨批次冷却，缓存/展示记录/历史同一事务写入。
- 收藏与已看拆分、熟悉/常看 UP、30 天关注窗口、原配额、原模型和真实曝光协议保留。经典推荐模式保持既有召回及耗尽回退行为。

## 验证

分阶段独立验证后推进：Ready/让位零网络、关注最新前缀和分区缺口、低/高水位、缓存快路径与幂等、发送层公平性与取消。每阶段在生产数据库副本上另采两批服务调用，均为零同步 API，耗时约 171～359 ms；部分后续批次只有 9 条，按约定直接返回短页，未为填满而降低质量或同步请求。阶段明细保存在 `.tmp/feed-optimization/phase1` 至 `phase5`。

最终全量后端 **95 项全部通过**，耗时 258.609 s：原 73 项（v0.3 30、v0.3.1 33、诊断 10）加优化回归 15 和真实传输协调 7。日志保存于 `.tmp/feed-optimization/final-tests.log`。旧数据兼容修复前的 94 项全量也已通过。

```powershell
.venv\Scripts\python.exe -W ignore -m unittest discover -s backend/tests -p "test*.py" -q
cd frontend
node tests/telemetry.cjs
npm run build
```

使用 `test*.py` 包含独立的诊断及优化测试；旧 `test_v0*.py` 命令只覆盖 v0.3/v0.3.1，不适合作为本轮全量验收。

低频真实边界核验（生产数据库临时副本，保留限速，关闭后台）：关注首屏 2310.10 ms，实际发送 head 1 次、detail 2 次，返回完整最新前缀 12 条、freshness=checked；同 view 重试 7.99 ms、零请求、结果相同。科技分区因 Ready 不足只发送 2 次 detail，耗时 2127.45 ms，返回 8 条短页后停止，未继续额外请求凑满。这三次只是功能/预算核验，样本数不足以估算稳定分位数。原始数据在 `.tmp/feed-optimization/network-boundaries/`。

新增关键覆盖：事务末尾缓存写入失败能回滚之前的 served/history 写入；同页并发只生成/记录一次；失败重试沿用 stream；跨 stream 在最终提交时重查原有两次未点击冷却；退出期间停止候选写入；成功 head 用完召回额度后仍能落库；真实 requests/urllib3 的重试、重定向、冷签名 nav、Retry-After 软截止、排队取消及前台优先级。

真实核验还发现已有 follow 候选中 11 条 pubdate 为字符串，导致最新时间线与数值时间戳比较失败。修复为候选读取时兼容旧字符串，新的动态接口记录数值时间戳，无需迁移数据库；新增混合旧/新发布时间顺序测试。发送后的落库检查只核对停止、风控和期限，不把已经用完的召回额度误认为成功结果不能保存。

前端 `npm run build` 通过，`node tests/telemetry.cjs` 的 5 个曝光/点击及重试场景通过。实际 FeedToolbar 组件的受控 React 渲染验证了候选准备、本地时间线降级、风控提示及换批按钮的禁用状态。热门和探索另用本地完整候选验证，均返回 12 条且外部请求为 0。Python 服务/工具编译与 diff 空白检查通过。

## 测量限制

未开启第二层深度埋点：SQLite_ms、逐条写入数量及候选命中比例仍为未测/null，不记成 0。原始 source 阶段信息和实际发送计数保留在 JSONL。当前无须网络新页的延迟已低于目标，没有触发进一步 SQL/JSON 调优的条件。

`bilibili_api_calls` / `detail_requests` 保留业务调用口径用于对照；预算以新增的 `http_attempts` / `detail_http_attempts` 实际发送口径为准，包含隐式重试和重定向。取消发生在发送前时，业务调用数可能高于实际发送数。

后台真实线上频率、失败率、短页率和长期来源分布尚未进行持续观察；优先级及后台补池由受控测试验证。本次 50 样本验收隔离了后台补池，证明热候选与缓存请求路径及生成竞争，不代表线上所有负载。前端验证为构建和组件渲染检查，未测浏览器端到端绘制时间；模型首次冷加载另有成本。
