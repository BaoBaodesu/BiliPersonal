# v0.3.4 策略盲评验收记录

日期：2026-10-07。范围：用户确认的 `policy-blind-v2` 计划，沿用 v0.3.3 推荐规则、五批／每组 Top12／五档评分和原五项护栏。

## 使用入口

启动服务后进入 **设置 → 推荐策略 → 策略盲评**（`/settings/policy-review`）。待评草稿不改变普通推荐；创建实验后冻结模型、公共控制、来源、实体词典及兴趣排序依据。候选不足显示准备状态，可继续使用普通页面。

评分按钮点击即保存；快捷键 `3 / 2 / 1 / 0 / -`，左右键导航，默认不自动前进。未保存或保存失败不能封存；封存有页面内确认，永久锁定。新增屏蔽使当前未提交批次整体作废，旧草稿保留。放弃实验要求原因，历史保留。

第五批提交自动生成报告；通过后确认配置差异，手动开始至少七个完整24小时的试用。任意时间可恢复启动前实际状态，满七天后手动保留。正常流程不需要停服务或编辑 JSON。

## 实现边界

- `policy_review` 为页面、CLI 共用入口。SQLite 增量增加实验、批次、评分三张表；评分使用条目版本和请求标识，封存／发布使用短写事务。
- 实验状态为 preparing、batch_ready、rating、completed、aborted、failed；准备状态单独保留检查、候选等待、差异等待和暂停原因。登录暂停保留账号归属和草稿，在途旧计算不能发布。
- 两组共用一个只读数据库快照、统一时钟和冻结排序依据；模型评分在读事务外进行，写入前复检版本及硬屏蔽。评分接口只返回白名单基础视频字段，不返回组别、来源、排序位置、推荐解释或模型分数。
- 同批共有 BV 共用分数，跨批重新评分。下一批须上批已提交、距上批冻结至少一小时、联合 Top12 至少50%向上取整为本轮此前未出现 BV，且两组各完整12条。
- 调度沿用原15／12／3每轮及240／40每小时预算，盲评需求排在普通需求之后；轮询不评分、不排序、不发远端请求。盲评不写 Feed 曝光、消费或冷却。
- 完成报告冻结总体、逐批指标和原五项护栏；平均分只作诊断。独立展示排序位置数、跨批评分次数与唯一 BV。无分母显示证据不足；零事件不证明零风险。
- 试用以自身 ID 汇总真实曝光、曝光后点击及每页前四位 CTR；模型／协议／词典变化需要重新盲评。设置变化不能偷偷切割七天证据；提前恢复保存原实际策略和参数。
- 旧 JSON 盲评作为只读历史，不取得新版准入；调试导入有版本及封存校验，原模型盲评命令语义保留。
